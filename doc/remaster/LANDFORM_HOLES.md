# Openings in the landforms ground (A10, VS-08; 25 November 2026)

The landforms ground (`DinkLandforms.cpp`, `UDinkLandformsSubsystem::BuildScreen`) is one procedural mesh per screen with an
opaque material, so nothing placed under it can be seen: the cracks, the pit and the cave mouths (25 placements) waited for a
way to open it. The code coordinator chose a hole list: per-screen polygons in a data file remove the ground's triangles
inside them. The list is **empty on master**, so nothing changes until the art side adds rows.

## The file

`DinkRemasterUE/Content/Dink/Data/Environment/landform_holes.json` (hand-written; `landforms.json` is generated by
`Scripts/export_landforms.py` and must not carry the rows):

```json
{
  "schema": "dink-landform-holes/1",
  "note": "free text",
  "holes": [
    {"id": "S089_P09", "screen": 89, "polygon_px": [[250, 180], [330, 180], [345, 230], [240, 232]], "floor_cm": -120,
     "note": "the pit (89/9): opening the size of the 1997 picture's dark part"}
  ]
}
```

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | Unique name. Use the placement the opening belongs to (`Snnn_Pnn`), with a suffix if one placement needs two polygons. |
| `screen` | yes | The screen number (`SCR_nnn` without the prefix). The screen must have landforms data (a row in `landforms.json`); a screen with flat ground sheets has nothing to open (the row is skipped and the unit test fails). |
| `polygon_px` | yes | Three or more `[x, y]` points in **map pixels** of that screen (x 0..600, y 0..400; map x = placement x - 20, the same as `placements.json` `map_x`/`map_y`). Any simple polygon; points in order round the edge (either direction). |
| `floor_cm` | no | Height in cm, above the flat 1997 floor (0), of the surface the drawn bodies, corpses and decor stand on inside the opening. Leave it out to keep the ground's own height there (nothing moves; right for a crack nobody stands in). Negative = below the floor. |
| `note` | no | Free text. |

## What the game does with a row

- The ground mesh: every triangle whose middle lies inside the polygon is left out. The opening therefore follows the mesh grid:
  5 map pixels near the player (about 20-50 cm in the world, by the screen's scale), 10 px on far screens. Draw the polygon a
  little inside the art's rim so the rim mesh covers the jagged edge.
- The vertices keep the ground's own heights (the rim stays where it was); the water quad of a shore screen is not cut.
- The surface the drawn layer stands on (`UDinkLandformsSubsystem::HeightCmAt`, `DinkLandforms::HeightCm` / `GroundAt`: Dink's drawn
  body and camera lift, lifted placements, decor instances) is `floor_cm` inside the opening when the row has one.
- Still a visual layer: the 1997 simulation (hardness, Dink's capsule on the flat floor, scripts, timing) does not read it; the
  probe md5s cannot change. The ground has no collision anyway, so the opening needs no collision change.
- Loaded at play start with `landforms.json`. A malformed file cuts nothing and logs `DINK LANDFORMS: ... no openings cut`;
  a good one with rows logs `DINK LANDFORMS: N openings in the ground`.

## Checks

- `python3 -m unittest DinkRemasterUE/Scripts/tests/test_landform_holes.py`: every row loads (schema, unique ids, screen has
  landforms, at least three points inside 600 x 400, area of at least one 5 px cell, `floor_cm` in range).
- `Dink.Movement.Landforms.Holes` (automation): the cut, the floor rule, malformed files refused, the shipped list loads.
- The look (does the art show through, is the rim covered) is a rendered check for the art side.
