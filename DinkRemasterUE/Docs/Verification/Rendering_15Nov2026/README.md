# Rendering and lighting realism pass, part 1 (15 Nov 2026)

Owner's order: "improve rendering and the realistic parts of it", photoreal. Renderer and lighting settings only (no
Blender, no new meshes or textures). Not in scope: cave/dungeon light levels (presentation-fixes stream), water and
ground materials (water and terrain streams), the house window lights (owner-approved 80 cm source height).

This first PR is cut short (account limit): it carries the measuring tools and the one change that was measured.
The fog and resolution changes that were prepared are NOT in it (see "Not done").

## How it was measured

Private project copy of master e803790d (world generated by the master importer), editor game (`run_capture.sh`,
offscreen Vulkan, AMD Radeon RX 6800 RADV), one session, all variants on the same frames, 5 s settle then 3 s
measured per frame. **Resolution caveat:** `-ResX/-ResY` do not reach the offscreen viewport; this run rendered at
1280x720 (100% screen percentage), not 1440p. `rendering_set.py` now sends `r.SetRes` (default 2560x1440) for
later runs. The editor game runs with `-norhithread -forcerhibypass` (offscreen stability), so fps is CPU-bound
around 65-95; the GPU ms column is the comparable number. Other agents' Unreal steps ran on the machine at the same
time (CPU contention; GPU ms is the least affected number).

## Found, not fixed (for other streams)

- World-edge band at the play camera on open screens (`r0_horizon_band_720p.jpg`: Darklands 28, coast 383,
  snowfield 47): the flat far backdrop skirt fogs to a pale sky-coloured strip under the backdrop hill ring, and the
  ring is green meadow even behind the Darklands and the snowfields. A lower fog density (0.002) is the prepared
  renderer-side fix (not measured yet); the ring's meadow material per region is a backdrop/terrain item.
- Goodheart castle walls and the KernSin fountain spray are still pixel cards (known Fable rows VS-02, VS-11).

## Not done (prepared on a local branch, not measured, so not in this PR)

- `environment.json` `outdoor` section applied at runtime by `UDinkEnvironmentSubsystem` (fog density 0.002).
- `[Rendering.AutoScreenPercentage]` in DefaultEngine.ini so a 1440p display renders at 75% (engine curve: about
  61%), 1080p at 82%, 4K at 67%. Needs the 1440p cost measured before it ships (target 60 fps at 1440p).
- No packaged-build frame time was measured (the packaged capture was queued, then cancelled at the account limit).
- The 1440p session (r1: base, three fog variants, sharpen, 75% and 100% screen percentage) was still waiting for
  its Unreal turn.
- Probe md5s were not re-run: nothing in this PR runs in a `-nullrhi` game (the sharpen is a post-process cvar, the
  console additions are review commands), so the traces cannot move, but that is reasoning, not a run.
