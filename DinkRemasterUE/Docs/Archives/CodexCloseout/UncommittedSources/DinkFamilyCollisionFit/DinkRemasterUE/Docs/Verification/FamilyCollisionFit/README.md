## Why script-ground anchoring

The audited original173/1 hardbox is37×21pixels. Its3m physical extrusion becomes254×144cm on031 and319×146cm on warped209, while the visible kit barrel is83.95×84.46×100.75cm. The family layer currently anchors that real-size mesh at the whole card's image center. `bin/dink/dink.ini` defines sequence173's pivot as `(41,44)` within source frame56×55, whereas whole-image horizontal center is28. The actual imported64×64 alpha texture's main opaque component normalizes to source x≈23.6..56, centered≈39.8, near that pivot. The left image margin is transparent, not another visible barrel. Centering a new3D mesh at the whole card center introduces the measured89.44cm/105.82cm horizontal shifts. The proposed transform instead puts the mesh's horizontal center/bottom at the unchanged actor/script ground point. Source sprite coordinates, Origin ID, script and drop coordinates are not moved.

## Implemented API

`DinkFamilyCollisionFit.h` defines the optional rule, authoritative sprite snapshot, exact cooked geometry and prepared candidate. Snapshot, geometry, candidate and authority are explicitly schema version1; mismatches refuse. `UDinkArtFamilySubsystem` adds:

- `PrepareCollisionFit`: reads one explicit rule, unique actual Origin actor/screen/family component and the current director-provided snapshot. Requires active hard173/1 with `prop==0`, matching runtime handle/origin/actor/current script and script XY matching actual actor ground within0.05cm. Its caller must populate that snapshot from the actual Director sprite under the loading gate, never infer current state from immutable Origin metadata.
- `ValidateCollisionFit`: rechecks actual world/Origin/source/script, actor and component transforms, mesh/BodySetup identity/GUID, materials, collision profile/enabled/type/all responses, navigation/overlaps, visibility, screen corners, unique ownership, current frame/hard/prop and policy. It rereads native cooked geometry and reconstructs the proposed transform, footprint, cells and height to reject stale/tampered payloads. Applied visual world transform allows0.0001cm numerical attachment recomposition tolerance; unchanged actor/card transforms remain exact.
- `ApplyCollisionFitVisual`: has no automatic caller. Requires an `IDinkFamilyFitVisualAuthority` supplied by the one admitted physical coordinator. That implementation must verify its loading gate and already committed matching logical+physical descriptor; a generic boolean approval is not the integration. Validation runs before and after this read-only acknowledgement. Only the noncolliding family child transform changes; no Origin/script/actor location, material, collision, navigation or card visibility setter is used. Failed publication must leave the coordinator gate held.

`ReadCookedGeometry` reads the actual loaded `CTF_UseComplexAsSimple` triangle mesh, records triangle order, positions, material indices and backface-ray policy, and hashes them. It never initiates a cook/save. The exact native digest must match the explicit rule. Render bounds remain83.95×84.46×100.75cm. Original75×75×100cm UCX vertices are verified and separately retained as provenance, **not substituted as query geometry**. This avoids both the old3m box and the UCX square's early diagonal corners. The future physical owner should install the same mesh/BodySetup and proposed TRS, or prove exact equivalent triangle/filter/material behavior before using a rebuilt representation.

`BuildFootprint` projects actual cooked vertices into world XY, computes their strictly convex CCW hull, and uses actual four screen corners for logical pixel-centre sampling. It rejects invalid/folded maps, nonfinite/degenerate geometry, clipped off-screen bodies and empty logical masks. `LogicalCells` are Y-major and are an explicit **cell-centre approximation**, not conservative dilation or exact arbitrary query geometry. Maximum half-cell world radius is recorded as the boundary quantization bound. Exact mesh physics remains authoritative for capsule/projectile/body contact; interaction must consume the same polygon/body rather than revert to the old giant rectangle. The convex projection fills holes/concavity in the logical footprint, appropriate only to this reviewed barrel shape; it is not a generic foliage/canopy algorithm.

## Strict optional policy, no shipped activation

The optional `collision_fit` object in the existing families schema has exactly `schema` (`dink-family-collision-fit/1`) and `origins`. Each origin row must have exactly `origin`, `family` (`barrel`), the exact kit mesh object path, a native-reviewed40-hex `geometry_sha1`, `anchor` (`sprite_ground`), `geometry` (`cooked_complex`) and `raster` (`cell_center`). One or both audited origins may be listed. Missing optional policy is a valid empty default. Invalid/duplicate/foreign/incomplete policy leaves no partial rules; `HasCollisionFitPolicyError()` distinguishes refusal from absence so a future marked coordinator cannot silently treat corrupted policy as legacy.

No such object is added to Data. Do not enable it until the physical consumer below exists and real native/current-world tests pass. Cooked triangle ordering/material indexing is target-specific: a source-editor digest is not automatically a packaged-platform digest. Validate the exact native/cooked asset identity for the target before admitting its policy.
