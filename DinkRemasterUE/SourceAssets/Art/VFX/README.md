# Procedural VFX source textures

Original, procedurally authored texture sources for the remaster's fire, smoke, spell, hit and pickup effects. Everything is generated by `tools/build_vfx.py` from fixed integer seeds with numpy and Pillow only: no downloaded images, no generative models, no input assets. Output is deterministic for a given numpy build. Status in the ledger proposal is `candidate`; nothing here is imported into Unreal yet.

```bash
# from DinkRemasterUE/ (about 2 minutes, one core, nice 10)
python3 SourceAssets/Art/VFX/tools/build_vfx.py
python3 SourceAssets/Art/VFX/tools/build_vfx.py --only fire,smoke   # subsets: fire smoke embers fireball glow hit masks noise
python3 SourceAssets/Art/VFX/tools/build_vfx.py --quick --out /tmp/vfx_quick   # reduced frame counts for iteration
```

It rewrites `Textures/*.png`, `Preview/*`, `vfx_manifest.json` and `ledger_rows_proposed.csv`. A partial (`--only`) run merges into the existing manifest and does not touch the ledger rows.

`vfx_manifest.json` is the machine-readable version: per texture the layout (columns, rows, frames, cell px, fps, duration, loop, seam quality), colour space, channel meaning, suggested Unreal import settings and Niagara usage. `ledger_rows_proposed.csv` has one row per texture in the exact column order of `SourceAssets/asset_ledger.csv`, for the owner of that file to merge (it is deliberately not applied here).

`Preview/` has a contact sheet for every flipbook and animated GIFs for fire, smoke (baked), fireball, hit flash and dust. `smoke_6way_relit_demo.gif` relights the loop with an orbiting light using only the six-way maps, which is the check that those maps really carry directional lighting. The `*_6way_*_rgb` sheets show the raw channels as colour.

## Methods

- **Noise**: own periodic 3D gradient noise (`vfxlib.Noise`) with per-axis lattice periods. Octave k uses period p*2^k, so shifting the sample position by exactly one base period loops every octave: flame and smoke loops are exact (loop-seam ratio in the manifest, about 1.0 or below means the first-to-last frame step is no larger than a normal frame step).
- **Fire**: tapering flame envelope eroded by anisotropic fBm that scrolls upward one lattice period per loop, with a second looping axis morphing the pattern, advected by the curl of a looping scalar potential (incompressible warp). Temperature falls with height; soot appears where it is cool and thin. Colour is the true Planck blackbody chromaticity (CIE 1931 multi-lobe fit, integrated 360-830 nm, converted to linear sRGB, 850-2350 K) with radiance compressed by a 0.42 exponent and a soft shoulder, because a raw Planck range of 1:100000 is not displayable.
- **Smoke / dust**: a 128x128x32 density volume per frame (curl-advected looping fBm inside a rising puff envelope; the dust puff is a radially expanding shell with noise advected outward). Transmittance towards each of the six axes comes from exclusive prefix sums, with Wrenninge-style multiple scattering (3 octaves, a=0.5, b=0.38) so shaded sides are not black. The result is projected along the view with front-to-back weighting, upsampled and given a soft border.
- **Hit flash**: analytic SDF composition (core, spikes, ragged shock ring, ballistic spark streaks), coloured through the same blackbody ramp.
- **Noise pack**: tileable Perlin fBm, Worley F1/F2/cell id (3x3 wrapped neighbourhood), curl from a periodic potential, blue noise by iterated FFT high-pass and rank remap.

## Import notes for Unreal (not done here)

- Flipbook frame order is row-major from the top left (Niagara SubUV). Every frame keeps a transparent border (at least 14 px per cell), so mips to about 1/8 do not bleed neighbours; for 6x6 atlases the cell is 341.33 px in Unreal and frames sit at `round(i*341.33)`, a sub-pixel difference.
- Colour textures are straight alpha with colour bled into transparent texels; use `rgb*a` in the material for additive/premultiplied use. Turn sRGB off for every data texture (Temp, six-way, noise, masks, LUTs, glow). Use `TC_BC7` for RGBA packs; masks and the glow can use BC4/grayscale. LUTs and curve rows need NoMipmaps and Clamp.
- See `vfx_manifest.json` for per-texture Niagara parameters. Still to build in the editor: the Niagara systems (house fire, fireball with light and ribbon, hit, pickup sparkle), the base materials (additive fire with LUT, six-way smoke, dust, glow), a half-resolution translucency/depth-fade setup and the lights, plus an eye check in the real game camera.

## Honest quality notes

Fire reads as flame at game scale and loops cleanly, but it is a single-tongue billboard: for a house fire it needs many overlapping instances with random frame offsets and scale. The look is noise-based, not a fluid simulation, so very close views will look softer than a captured plume. The smoke puffs are soft and plausibly lit but are generic cloudy billows, not a tall rising column; the six-way maps are physically motivated yet unverified in the engine (axis conventions: +X right, +Y up, +Z toward the camera; the preview GIF validates them internally only). Hit flash and dust are stylised and tuned by eye. Ash flakes are simple torn-paper shapes. 8-bit PNG limits the HDR range: emissive strength comes from material multipliers, and the temperature texture is 8-bit, so a 16-bit EXR/TGA variant would be better if banding shows in slow fades.
