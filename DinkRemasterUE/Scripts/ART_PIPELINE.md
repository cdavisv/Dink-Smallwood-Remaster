# Blender art import and verification

The source workflow follows the companion repository's `tools/blender/CONVENTIONS.md` and `tools/blender/README.md`, plus `doc/remaster/REMASTER_PLAN.md`: real dimensions in metres, applied transforms, origin IDs, PBR maps and separate source assets. Editable sources and measured validation results live under `SourceAssets/Art`. The original sources and procedural textures have ledger entries; imported `.uasset` files are derived output.

Use `Scripts/import_stonebrook_art.sh` for the interior and `Scripts/import_stonebrook_exterior.sh` for the cottage yard. Both run an unattended Python commandlet, save full logs under `Saved/Logs`, and publish a runtime manifest only after every mesh has the expected dimensions and material slots. Runtime `UDinkArtSubsystem` applies those manifests without editing `_Generated` maps. Missing assets leave that screen's greybox intact.

The interior uses authored collision, replacing the original flat-game furniture hardboxes. Collision follows the mesh triangles and preserves the open doorway; the player has a 28 cm capsule radius. The physical props retain their original live actors, scripts, vision flags and save IDs. Decorative art uses nonpersistent actors created at startup. Grass and dirt overlays can opt out of collision. The local room exposure volume blends independently from the outdoors.

Important verified import details:

- Blender metric unit scale 1, FBX `UnitScaleFactor=100`, imports at scale 1 as centimetres. The importer checks every axis against source dimensions with a 1 cm tolerance.
- FBX mirrors Blender Y in Unreal. The 2 m interior floor/ceiling modules extend toward negative local Y, so their NW layout anchors need a scaled 2 m southward offset. The original missing offset left a real floor hole, caught both by swept walking and desktop keys.
- UE 5.8 Interchange can intercept FBX even when an explicit `FbxFactory` is supplied. This importer selects the documented legacy FBX path. Reimport reads the existing mesh's `asset_import_data`, so it must also receive the unit settings, and its filename must be retained. Losing that filename makes a headless reimport attempt a Slate file picker and crash. The reproduced crash stack identified `FReimportManager::GetNewReimportPath` and `OpenFileDialog`; retaining the source path fixes it.
- Base colour is sRGB. ORM is linear masks (R AO, G roughness, B metallic). Normal maps use normal compression, green-channel flip and a reduced XY strength matching the Blender preview. Rigid meshes use Nanite with a full-triangle fallback, and their materials explicitly save the Nanite usage flag to prevent default-material fallback. Foliage retains conventional LODs. Once imported correctly, Unreal's mesh bounds match source LOD0; the 1 cm check uses its dimensions. Separately measured union bounds remain source diagnostics, and tests require all three actual LODs.
- The companion FBX exporter writes foliage LOD siblings rather than an FBX LODGroup. Combining that file in Unreal merges the LODs into one mesh; names alone do not establish the chain. The local art bridge exports one FBX per foliage LOD, imports only LOD0, and attaches LOD1/2 with `StaticMeshEditorSubsystem.import_lod`. In a commandlet the subsystem instance is absent; the verified class default object exposes the stateless editor API. The art test requires all three actual loaded LODs.
- The importer and runtime compare/log physical dimensions; the two `Dink.Art` tests verify loaded meshes, materials and expected LOD counts. A rendered playtest is still required for lighting, composition and camera clearance.
- A bounded `UPostProcessComponent` needs a query-enabled parent shape for its containment query; ignore all collision responses and disable overlaps so the exposure box cannot affect movement.

Run `Scripts/build.sh` and `Scripts/test.sh` after C++ changes. `Scripts/test.sh Dink.Import.Greybox.Stonebrook` checks the actual walking loop; `Scripts/test.sh Dink.Art` checks the imported kits. `Scripts/Playtest/README.md` describes the actual keyboard routes and screen capture tools. The desktop driver refuses input if the Dink viewport loses focus.

These are art candidates for the starting house and yard. The house-fire variants and wider world still require production work. Authored actors use geometry-based interaction reach; undressed and virtual actors retain classic pixel rules. Reach values live in `Content/Dink/Data/Interaction/authored.ini`. Ground pickups use 30 cm beyond the capsule; raised items use 85 cm, with a 45 cm minimum elevation and a 140 cm shoulder sightline that still rejects walls. The rendered regression caught a pie that was unreachable behind a chair after remote collection had been fixed. Physical item contact, talking, attacks, occlusion and removal have dedicated regression checks and rendered keyboard fixtures.

## Authored humanoids

`Scripts/export_character_reference.sh` exports the installed Epic mannequin rest rig and idle preview to `/tmp/dink-character-reference` (override `DINK_REFERENCE_DIR`). These files are animation-fitting references, not CC0 art. UE 5.8.4 skeletal FBX export needs rendering resources even when material baking is disabled: use offscreen GPU rendering, not `-nullrhi`, which was observed to assert in CPU-skinned mesh export. The wrapper disables crash reports.

Character sources live in `SourceAssets/Art/Characters`, with independent provenance for the MakeHuman/MPFB CC0 body and textures. Blender source scenes remain in metres. For FBX, temporarily scale mesh coordinates and edit-bone translations to centimetres, use unit scale .01 and `FBX_SCALE_ALL`, and restore metre authoring afterwards. Preserve all reference bone transforms, including the explicit identity `root` bone. An imported FBX root may become a Blender armature object; renaming that object alone does not recreate the missing root bone. A root rotated 90 degrees can preserve the visible rest pose while breaking every animation.

`Scripts/import_character_art.sh` validates the independently imported mesh against the installed reference before assigning the existing animation skeleton. It checks bone names, hierarchy, local translation, rotation, scale and real dimensions, then imports four separate LOD FBXs and assigns the five materials. The original skeleton's reference pose is never updated. UE 5.8 does not expose `SkeletalMesh.Skeleton` assignment to Python; `DinkCharacterArtLibrary.assign_matching_skeleton` checks the complete bind pose again in native code and assigns only the candidate mesh. Reimports can omit automatic Physics Asset creation, so the bridge explicitly uses `SkeletalMeshEditorSubsystem.create_physics_asset` when needed and saves the result. Normal locomotion uses the separate capsule, without enabling skeletal-body collision. The atomic runtime manifest `Content/Dink/Data/Art/characters.json` is published only after these checks succeed.

`UDinkHumanoidComponent` animates the original script actor with the existing locomotion blend space. It measures actual movement and returns to idle after teleports; it does not require a Pawn animation blueprint. The original placement, script, save identity and vision controls remain on the actor. A separate capsule supplies the physical body and interaction target. `Dink.Art.HumanoidPresentation` exercises these behaviours on a plain actor; `Dink.Art.CharacterBindPoseAndMaterials` verifies the delivered skeletal asset and LODs.


## Pig pen and own-rig creatures

`Scripts/import_pigpen_art.sh` imports the wheat scatter and reuses explicit StonebrookExterior asset paths for screen407. It publishes `pigpen.json`; set `DINK_ART_OUTPUT_NAME` for another screen so a new environment import cannot overwrite the courtyard manifest. Runtime environment dressing discovers sorted JSON files and accepts only its own schema. The original west gate, five pig origins, feed box and scripted eastern entry corridor remain intact. Only ground and fencing collide; grain, grass, dirt and small stones do not.

`Scripts/import_creature_art.sh` imports the original Blender pig from `SourceAssets/Art/Creatures/Pig/pig_manifest.json`. It has its own26-bone quadruped skeleton, three explicitly imported mesh LODs, four materials and a saved Physics Asset. Four30fps in-place clips feed `BS_Pig_Locomotion`: Idle0, Walk80cm/s and Run400cm/s; Feed is a0.4s nonlooping nibble. Native inspection checks imported duration, finite poses, root drift, scale and loop seams before atomically publishing `creatures.json`. All import/reimport source paths resolve to the permanent source directory, including when running a staged project.

`UDinkCreatureSubsystem` attaches presentation and fitted trunk/head box components to the existing actors. `UDinkCreatureComponent` measures actual movement and scales Run playback above its nominal speed, preserving the original brain's positions and timing. Feeding requires an actual visible430/431 grain actor, a stopped pig, head proximity, forward direction and an unobstructed trace. The visibility trace targets the visible grain mesh bounds near ground level; the legacy marker root stays60cm high for original script compatibility. Reach and heading remain horizontal tests. Hidden authored grain cannot fall back to an invisible root target. Movement interrupts the visual nibble; no brain/property writes are used. `dink.Creatures` prints measured speed, actual heading, head position and feeding state. Original die/save behavior still hides the pig and disables its collision.

Authored normal-brain motion checks proposed-facing compound box geometry and commits the accepted actor heading. A final pose check prevents a failed move's auto-reversal from rotating the body through a fence. Existing overlap escape, scripted movement and explicit `sp_nohard` retain their separate behavior. Headless gates in the isolated pig-pen project passed `Dink.Gameplay.AuthoredGeometry`8/8 and `Dink.Art`9/9 with zero warnings. Rendered feeding and final integration are separate acceptance gates.

While the owner uses the live game, build and test in `/tmp/dink-pigpen-stage`: Source/Plugins/Config/Scripts, Binaries, Intermediate and Saved are independent; Content/SourceAssets/ImportData link to production. This protects the running game's shared libraries and save files. Do not rebuild the live project's libraries or close a user-focused game. Record source snapshots and use distinct `DINK_TEST_RUN` names; staged results do not establish that the old live executable includes the new code.


`Scripts/import_milder_art.sh` incrementally imports `Characters/Milder/milder_manifest.json` and merges the successful result into the runtime character manifest. It preserves existing hero/mother entries and assets. The global source manifest includes the same SK_Milder/materials and `s1-bul` script profile for later complete regeneration. Dynamic script attachment, restored actors and size changes use `UDinkArtSubsystem::ApplyScriptCharacter`; the generic cylinder's nonuniform scale is normalized before attaching the model/capsule. Feet remain grounded when `sp_size` changes. The original script, handle and saved facing remain authoritative. Milder's editable original armor/cloth overlays CC0 MakeHuman anatomy, shares the exact89-bone installed animation rig, and has four explicit LODs.

Outdoor review revision `skin-muzzle-linear-half-v2` reduces only the pig's Skin/Muzzle albedo. Its mesh/UV/weights/rest/action fingerprint is unchanged; normal/ORM and all seven FBXs remain byte-identical. The source backup and correction report are under `Creatures/Pig/Working`; the durable phase copy is `Saved/PigPenStage/pig_albedo_v2_validation.json`. The rendered comparison passed for this iteration; coarse close-range pores remain candidate polish.

`dink.LegacyCardsCurrentScreen` defaults to1: original undressed placement cards and background sprite instances render only on the current gameplay screen. Authored3D geometry, ground, actor-hidden/vision flags, collision and script/save state are unchanged. Set it to0 to restore the original all-loaded-screen card visibility. Undressed neighboring screens temporarily show ground only until entered; logical screen transitions can expose their remaining legacy art. This contains the horizon of towering flat cards while replacement art is still being developed.

## Oak floor and render-only underfloor

The incremental starting-house surface workflow is documented in [FLOOR_SURFACE_PIPELINE.md](FLOOR_SURFACE_PIPELINE.md). It preserves the original floor geometry, UVs, nails and collision while assigning a new wood material to a unique mesh copy. BC gain1 and normal strength1 use the accepted Blender bakes directly. The original generated oak reference, full prompt and art-directed scale calibration remain in the source bundle.

A separate contour-fitted underfloor is entirely render-only. Its source guide result has one explicit collision-missing exception, with all other checks passing; do not generate collision for it. The context actor supplies owner-screen visibility, no collision/navigation/overlap events and no hidden shadows/GI. Actual native import dimensions are1486.9421387×1311.75×2cm,24vertices/44triangles, topZ=-16cm. The original walking floor remains unchanged.

Native saved-package inspection and source/publication guards accompany both assets. The material helper is editor-only and read-only; native input inspection covers pins omitted from Python enums. Runtime readers in editor-game mode may need exact native reflected property names such as bCanEverAffectNavigation and bHasNavigationData rather than their unavailable Python aliases. Final native tests, real-keyboard routes and matched-camera captures are recorded in Docs/Verification/SurfaceFinish.
