# Fireplace refinement pipeline

The Blender source remains separate from the original Stonebrook kit. Its candidate plan preserves P19’s origin/offset/rotation/scale and original s1-h1-2 script. It selects the unique mesh under Dink/Refinements/FireplaceV2 and the existing local fire light at40lm/2000K/55cm; global exposure and other lights are unchanged.

Run `Scripts/import_fireplace_refinement.sh` to create the unique packages if missing, then validate them. Existing packages are checked rather than silently reimported. `DINK_FIREPLACE_MODE=check` makes no asset or Data changes; it validates geometry, materials and any published layer. `DINK_FIREPLACE_MODE=publish` validates existing packages, writes stonebrook_refinement_fireplace_v2.json, then updates only the matched original local-light row. Publish only into a stopped project after its rendered/gameplay gates. Reapply the refinement after regenerating original Stonebrook lighting. The separate sorted art layer keeps its geometry replacement from being lost during original-kit regeneration.

The source specifies Nanite=yes. The importer enables Nanite material usage and explicitly selects PercentTriangles with a1.0 fallback fraction and0relative error, preserving15484/8050/4180 authored fallback triangles. Auto can reduce the fallback despite the1.0 fraction. Imported source vertices and full Nanite triangle count verify actual geometry dimensions. GetBounds may include Nanite’s expanded coarse-LOD culling envelope, or cached source bounds; the report records that separately from actual source-vertex dimensions. Collision uses the six fitted imported convex hulls through simple-as-complex.

`configure_fireplace_render.py` is an explicit pre-release candidate-only correction tool for the initial classic-render diagnostic import. It backs up only the new mesh/material under Saved/FireplaceV2Integration/BeforeProductionRender, enables the source render policy, and validates afterward. It does not modify the original kit. Normally a fresh import already has the correct policy.

Refinements is included in package.sh’s existing-directory cook list because runtime JSON paths do not establish cook references. Native editor and render checks do not prove a packaged build; verify a new cook separately. Source records stay candidate until a person approves their artistic quality.
